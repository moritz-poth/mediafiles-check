# MediaFiles Check – notes for working on the project

Cross-project rules (menus, About, Settings, languages, updater, logging, publishing): skill `~/.claude/skills/moe-apps/SKILL.md`.

Small Mac app (Rust core + Slint, same look as MediaFiles Ferry) that compares every `Avid MediaFiles/MXF/<folder>` with its Avid database `msmFMID.pmr` and lists the differences. Sister project of MediaFiles Ferry (the user wanted it as its own app, not inside Ferry). GPL-3.0; GitHub account moritz-poth (not published yet). Users: editors and assistants without a technical background.

## Fixed rules
- Checking only reads. The only writes: renaming folders for Media Composer and back, and moving new files on rename back – both only when the user asks. Never delete, never overwrite (check `exists()` first – `rename(2)` replaces an empty folder or a file silently).
- Renaming (`src/rename.rs`): Media Composer only updates folders named with a number (local drive) or `<ComputerName>.<number>` (network drive, `statfs` without `MNT_LOCAL`). Only folders directly in `Avid MediaFiles/MXF` are renamed. The journal (`renamed.json` in Application Support: original name, every MXF file name + size, database stamps) is saved before each rename; an unreadable journal disables renaming. "Ready" = both database files exist and changed since renaming. Renaming back asks about new files (move to new folder / to `1` or `<computer>.1` / keep), missing or changed files and a not yet rewritten database. Media Composer must be closed: `pgrep -x AvidMediaComposer` (not `-f`: AvidBackgroundServicesManager lives in its bundle and always runs).
- `msmFMID.pmr` format is reverse-engineered (`read_pmr` in src/lib.rs, layout in the module comment). Block 1 = names in Mac Roman, leaving out names it can't represent; block 2 = all names in UTF-8 and authoritative. Block 1 is only a plausibility check (not longer, its ASCII names in block 2); the file must end exactly after block 2, otherwise "unreadable" – never guess. Verified against the Ferry test environment and one of the user's media drives (Media Composer 2024 databases with umlauts and Turkish names).
- Names are compared with `key()` (NFC + lowercase). Dot files and subfolders (Avid's "Creating") are ignored.
- Four languages: en, de, fr, es (the user's rule for all apps). Core texts (findings, report) in `Finding::describe` / `report_text` via `pick()`; UI texts English in `@tr()`, translations in the table of `scripts/translations.py`, which writes the three `.po` files and fails if an `@tr` has no entry – run it after every UI text change. Manuals `docs/help/<code>.md` for all four.

- Avid bins: `src/avb.rs` reads `.avb` (format from pyavb, MIT – THIRD-PARTY.md; running pyavb itself is not allowed here, it is only a reference). Parses only mobs (CMPO), source clips, sequences, track-group prefixes, descriptors + locator class; skips everything else. Bin items include hidden file mobs: shown = Master (subclip: usage 2) and Composition with usage 0 (sequence). File mob = source mob with a media file descriptor; its mob ID is the **first** 32-byte ID of the msmFMID.pmr record (`read_pmr_entries`), verified on a real test project. Names in bins are Mac Roman. Checked: all 6583 bins of the user's test projects (path: see local memory, not in the repo) (MC 18.12–26.8) read without error (`mfcheck --bins`, `MFC_DRIVES=a:b` adds the ID match).

- Avid projects (`src/projects.rs`, `ProjectsWindow`): project = folder with an `.avp` (no search inside a project – shared projects have more .avp in AvidSharedData), bins without `Attic`. Bin items are all mobs, Media Composer hides most: shown clips = masters, subclips (usage 2), sequences (composition, usage 0). Master usage 1 = render (precompute) master "<sequence>,<effect>,<n>" – their missing files are only counted (`renders`), not listed or requested (test project: 919 render vs 17 real). Result per bin: missing files grouped by name (master clip that owns the file, else file mob name – often just "File" – else first use), each with its uses; ProjectsWindow is 680 px wide, `MissingList` rows open per group (`ProjectsState.open`). References to mobs in other bins are resolved per project. Available = first ID of every msmFMID.pmr entry whose file is really in the folder, plus MXF files in no database identified by their header (`src/mxf.rs`: essence container data → LinkedPackageUID = file package UMID; material number's first three fields big-endian in MXF, swapped to the pmr/bin layout – verified identical to the pmr ID for all ~8,700 files of samples from three of the user's media drives and the Ferry test environment); dot files (AppleDouble `._`) skipped; a drive silent for 30 s is skipped (`available_media`, hanging macFUSE/network mounts block forever). AMA = media descriptor with extension 0x01 (acfUID of the AMA plugin; `Mob::ama`) – AMA files still carry an MSML locator, so the locator says nothing; 4 test projects: 790 AMA file mobs, none in any msmFMID.pmr – not requested; listed per bin with their uses (`ScanResult::ama_by_bin`) in their own `AmaWindow` ("Show AMA clips…" in the result, own open set `ProjectsState::ama_open`, hidden when a new scan starts) and in the saved list. An AMA file whose master clip has a namesake master in the same project with all its media on the drives (linked first, imported later) is left out (`ama_covered`, only counted). Relink = missing file whose source (name of the tape/camera/import source mob below the file mob, `Bin::source_name`, + picture/sound) belongs to an available file mob in the scanned bins (e.g. re-transcoded dailies: new file mob IDs, old bins still point to the old ones) – marked, not requested. "Unmanaged" = file mob without MSML locator (AAF imports) – counted separately, still requested (Ferry only finds what is in Avid MediaFiles). File mob without any locator = no media was ever made (camera sound tracks of camera master clips when only the picture was delivered and sound comes from an external recorder; test project: 839 of 883 "missing") – left out, counted as `no_media`. A source clip points at one track (track number + media kind) of its mob; `Bin::used_tracks` follows only that one (a picture-only subclip must not need the camera sound), all tracks if it is not found. Request = JSON `{format: "mediafiles-ferry-request", version, system, created, files: [{id (64 hex), clip, bin, project}]}`, file `YYMMDD-HHMM_<computer>_Request.ferry`; Ferry reads it in `src/request.rs` (keep both sides in step). Windows that grow stay unpainted below their old height on macOS: every window reports height changes (`CheckWindow`: `changed height => Shared.resized()`) and is wired with `repaint_on_resize!` (app.rs) – use it for any new window.

## UI
Fixed width 420 px (projects window 680 px; wrapping texts there use the full layout width – a narrower fixed width makes Slint measure one line too few), height from content; pages home / working / result / rename / question / notice in one window; JetBrains Mono, title in Helvetica Neue Light, colours only from `Theme` (copied from Ferry). Menu: app menu → About opens our `AboutWindow`, app menu → Settings… (⌘,) opens `SettingsWindow` (appearance `Switch`, language `Dropdown` = Mountpoint's dropdown with a native menu) – `mac_menu` in app.rs swaps NSApplication's About panel methods and adds the Settings item (re-added after Slint's menu rebuilds via `setMainMenu:` swizzle, a timer after language changes and the 2 s timer); Help → Manual, Show Log File (`src/log.rs`, `~/Library/Logs/MediaFiles Check/`) (`HelpWindow`, content from `docs/help/<code>.md`, split by `help_blocks` – same as Ferry; paragraphs need a fixed width or the scroll height comes out too short). Drive list: green dot (drive ready), name, `Switch` on the right (Mountpoint style) (new drives ticked), polled every 2 s on the start page (`sync_drives`). Settings in `~/Library/Application Support/MediaFiles Check/settings.txt`. The result shows up to 10 file names per finding; the saved report has all.

## Updates
`src/update.rs` (identical to Ferry's apart from the first comment line): port of Mountpoint's Updater.swift through /usr/bin/curl; checks 5 s after start, every 6 h and from Settings (UPDATES section); banner on top of the main window (`UpdateOffer`/`UpdateStatus`); install = download → ditto → bundle id + `MediaFilesCheckRelease` (Info.plist, written by the build script) == tag + `codesign --verify --deep --strict` → old app to ~/.Trash → new app in place → shell waits for the pid and reopens. Release tags `v<version>`, asset `MediaFiles-Check-<version>.zip`. Beta 1 has no updater – users of it update by hand once. `UPDATE_IT=1 cargo test live_github` asks GitHub. Update signature (since 1.0.0-beta.6): every zip is signed with Ed25519 (`<zip>.sig`, `scripts/update-key.swift`, private key in the login Keychain as "MediaFiles Check update key"); `UPDATE_APP.public_key` holds the public half; `newest_release` ignores releases without `.sig`, `download` checks it before unzipping (`signature_valid`, crates ed25519-dalek + base64). build-mac-app.sh signs only if the Keychain key matches, else prints "NOT SIGNED". Never replace the key (installed apps trust it). Older betas (≤ beta.5) don't check signatures and update normally.

## Support
Settings → SUPPORT (same flow as Mountpoint): "Run self-test…" (`src/selftest.rs`: database, compare, MXF header, rename and back, drives readable (listing only, 30 s timeout), log, update download + signature, Media Composer running – all on test data in `$TMPDIR/MFCSelftest-…`, own rename journal there, never the user's), "Report…" (problem form), "Show log file", "Buy me a coffee" (buymeacoffee.com/moritzpoth; README line under the intro). Pages inside `SettingsWindow` (`page` 0/1/2), Rust in `wire_support` (app.rs). Reports (`src/report.rs`): same JSON as Mountpoint plus `product: "mediafiles-check"`, POST via curl to the Mountpoint worker (`worker/` in the Mountpoint repo), which files them in the private repo moritz-poth/mediafiles-check-reports; sending fails → saved in Downloads; `anonymize()` hashes folder/drive names in paths, user/computer name, server URLs. Result = toast over the settings (3 s / 8 s); after a successful send back to the settings page. Check titles are translated in `selftest::title`, ids and details stay English. Unit tests never write the user's log (`log::write` is a no-op under cfg(test)).

## Docs
Update `docs/help/*.md` and README with every feature change. The manual shows pictures: a line `![alt](images/<lang>/x.png)` (path relative to docs/help, same on GitHub) becomes a framed picture block (`help_picture`; in the bundle under Resources/help, copied by the build script; 2x PNGs shown at half size). README pictures: `assets/screenshots/<name>-dark|light.png` in `<picture>`. Screenshots were made with a temporary hook (demo data, `window.take_snapshot()`, cut at the divider lines without headline and side padding), then removed – redo the same way when the UI changes; no real drive or project names.

## Build / test
`cargo test`, `scripts/build-mac-app.sh` → universal `dist/MediaFiles Check.app` + zip (ad-hoc signed). CLI `mfcheck [--de] [paths]` runs the same check. Test data: the Ferry test environment and the user's test projects (real names inside – paths only in local memory, never commit). Visual check: launch the app, `screencapture -l <window id>`. Before handing a build over, start the **bundle** with `open "dist/MediaFiles Check.app"` – the bare binary behaves differently at launch (a menu change that worked from `target/` crashed the bundle). Crash reports: the log file (panic hook) and `~/Library/Logs/DiagnosticReports/`.
