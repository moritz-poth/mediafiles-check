# MediaFiles Check – notes for working on the project

Cross-project rules (menus, About, Settings, languages, updater, logging, publishing): skill `~/.claude/skills/moe-apps/SKILL.md`.

Mac app (Rust core + Slint) for the Avid MXF media of edit systems. Since 2026-11-09 it is ONE app with MediaFiles Ferry (user decision; Ferry as a separate app goes away): Exchange (Ferry), Check (every `Avid MediaFiles/MXF/<folder>` against its database `msmFMID.pmr`), Projects, Maintain, Tasks. UI design: `~/Documents/MediaFiles UI Entwurf/` (HANDOFF.md, mockups). GPL-3.0; GitHub account moritz-poth (not published yet). Users: editors and assistants without a technical background.

## Fixed rules
- Checking only reads. The only writes: renaming folders for Media Composer and back, and moving new files on rename back – both only when the user asks. Never delete, never overwrite (check `exists()` first – `rename(2)` replaces an empty folder or a file silently).
- Renaming (`src/rename.rs`): Media Composer only updates folders named with a number (local drive) or `<ComputerName>.<number>` (network drive, `statfs` without `MNT_LOCAL`). Only folders directly in `Avid MediaFiles/MXF` are renamed. The journal (`renamed.json` in Application Support: original name, every MXF file name + size, database stamps) is saved before each rename; an unreadable journal disables renaming. "Ready" = both database files exist and changed since renaming. Renaming back asks about new files (move to new folder / to `1` or `<computer>.1` / keep), missing or changed files and a not yet rewritten database. Media Composer must be closed: `pgrep -x AvidMediaComposer` (not `-f`: AvidBackgroundServicesManager lives in its bundle and always runs).
- `msmFMID.pmr` format is reverse-engineered (`read_pmr` in src/lib.rs, layout in the module comment). Block 1 = names in Mac Roman, leaving out names it can't represent; block 2 = all names in UTF-8 and authoritative. Block 1 is only a plausibility check (not longer, its ASCII names in block 2); the file must end exactly after block 2, otherwise "unreadable" – never guess. Verified against the Ferry test environment and one of the user's media drives (Media Composer 2024 databases with umlauts and Turkish names).
- Names are compared with `key()` (NFC + lowercase). Dot files and subfolders (Avid's "Creating") are ignored.
- Four languages: en, de, fr, es (the user's rule for all apps). Core texts (findings, report) in `Finding::describe` / `report_text` via `pick()`; UI texts English in `@tr()`, translations in the table of `scripts/translations.py`, which writes the three `.po` files and fails if an `@tr` has no entry – run it after every UI text change. Manuals `docs/help/<code>.md` for all four.

- Avid bins: `src/avb.rs` reads `.avb` (format from pyavb, MIT – THIRD-PARTY.md; running pyavb itself is not allowed here, it is only a reference). Parses only mobs (CMPO), source clips, sequences, track-group prefixes, descriptors + locator class; skips everything else. Bin items include hidden file mobs: shown = Master (subclip: usage 2) and Composition with usage 0 (sequence). File mob = source mob with a media file descriptor; its mob ID is the **first** 32-byte ID of the msmFMID.pmr record (`read_pmr_entries`), verified on a real test project. Names in bins are Mac Roman. Checked: all 6583 bins of the user's test projects (path: see local memory, not in the repo) (MC 18.12–26.8) read without error (`mfcheck --bins`, `MFC_DRIVES=a:b` adds the ID match).

- Avid projects (`src/projects.rs`, tab Projects – formerly `ProjectsWindow`/`AmaWindow`, now steps Choose projects / Missing media / AMA clips / Request in `ProjectsPane`): project = folder with an `.avp` (no search inside a project – shared projects have more .avp in AvidSharedData), bins without `Attic`. Bin items are all mobs, Media Composer hides most: shown clips = masters, subclips (usage 2), sequences (composition, usage 0). Master usage 1 = render (precompute) master "<sequence>,<effect>,<n>" – their missing files are only counted (`renders`), not listed or requested (test project: 919 render vs 17 real). Result per bin: missing files grouped by name (master clip that owns the file, else file mob name – often just "File" – else first use), each with its uses; ProjectsWindow is 680 px wide, `MissingList` rows open per group (`ProjectsState.open`). References to mobs in other bins are resolved per project. Available = first ID of every msmFMID.pmr entry whose file is really in the folder, plus MXF files in no database identified by their header (`src/mxf.rs`: essence container data → LinkedPackageUID = file package UMID; material number's first three fields big-endian in MXF, swapped to the pmr/bin layout – verified identical to the pmr ID for all ~8,700 files of samples from three of the user's media drives and the Ferry test environment); dot files (AppleDouble `._`) skipped; a drive silent for 30 s is skipped (`available_media`, hanging macFUSE/network mounts block forever). AMA = media descriptor with extension 0x01 (acfUID of the AMA plugin; `Mob::ama`) – AMA files still carry an MSML locator, so the locator says nothing; 4 test projects: 790 AMA file mobs, none in any msmFMID.pmr – not requested; listed per bin with their uses (`ScanResult::ama_by_bin`) in their own `AmaWindow` ("Show AMA clips…" in the result, own open set `ProjectsState::ama_open`, hidden when a new scan starts) and in the saved list. An AMA file whose master clip has a namesake master in the same project with all its media on the drives (linked first, imported later) is left out (`ama_covered`, only counted). Relink = missing file whose source (name of the tape/camera/import source mob below the file mob, `Bin::source_name`, + picture/sound) belongs to an available file mob in the scanned bins (e.g. re-transcoded dailies: new file mob IDs, old bins still point to the old ones) – marked, not requested. "Unmanaged" = file mob without MSML locator (AAF imports) – counted separately, still requested (Ferry only finds what is in Avid MediaFiles). File mob without any locator = no media was ever made (camera sound tracks of camera master clips when only the picture was delivered and sound comes from an external recorder; test project: 839 of 883 "missing") – left out, counted as `no_media`. A source clip points at one track (track number + media kind) of its mob; `Bin::used_tracks` follows only that one (a picture-only subclip must not need the camera sound), all tracks if it is not found. Request = JSON `{format: "mediafiles-ferry-request", version, system, created, files: [{id (64 hex), clip, bin, project}]}`, file `YYMMDD-HHMM_<computer>_Request.ferry`; Ferry reads it in `src/request.rs` (keep both sides in step). Windows that grow stay unpainted below their old height on macOS: every window reports height changes (`CheckWindow`: `changed height => Shared.resized()`) and is wired with `repaint_on_resize!` (app.rs) – use it for any new window.

## Rebalancing
`src/rebalance.rs` (user requests 2026-11-09). Limit = all files incl. the two database files (`per_folder` = limit − 2 media files; Settings → Rebalancing tab, id 4 shown second; line 5 of settings.txt, 100–50000, default 5000). Every change of the limit goes through a warning card in the settings window (field + "Change…"/Enter → `limit-ask`; Cancel reverts the field) – the user wanted one fixed rule instead of a per-group choice: groups are ALWAYS laid out anew for the current limit.
Group = main folder + "<base>-rebalanced-<n>" folders in the same MXF folder, found BY NAME (base = name without ".<digits>"; also works for other workstations). `plan()` sorts all MXF files of the group by creation date (fallback modification date): oldest `per` → first rebalanced folder, … youngest stay in the main folder; the files of one clip (same master mob ID: msmFMID.pmr second ID, else MXF header material package 0x4401 – needed while databases are set aside, so a second run plans no moves) stay in one folder (`layout`: a clip that does not fit starts the next folder, only a clip larger than `per` is split – idea from MediaMuster, 2026-11-10); existing rebalanced folders keep their names, missing ones get the next free number, emptied ones holding only leftovers (`is_leftover`: msmFMID.pmr, msmMMOB.mdb, an empty "Creating" folder, hidden files) go as a whole into "<drive>/MediaFiles Check Database Backups/<time> <name>" (`move_leftover`); with anything else in them only their database is set aside and they are kept (never deleted with content). Lower limit → more folders, higher → files move back. Layout comes from the drive, so an interrupted run is finished by the next one. "Find full folders…" (`full_folders`) lists groups where something would move; groups with a folder currently in renamed.json are `blocked` (names reserved).
Media Composer's own main folders ("1" local, "<computer>.<n>" network, `is_mc_folder`) → page `askname` before the run: we recommend a name of its own (`check_name`: not empty, no "/" ":" leading dot, not an MC name, no "-rebalanced-", not taken); the main folder is renamed (one rename) and the group gets the new name, old "1-rebalanced-N" folders fold into it. "Keep the name" skips.
History: rebalanced.json, ONE entry per group (`Journal::find` by mxf + main name), saved before anything moves; fields `renamed_from`, `folders`, `files`, `changed` (folders whose databases need rewriting; an unfinished run's list is merged into the next), `db_done` (old entries without it count as done; old `moved` lists still read). Start / "Rewrite databases" (`rewrite_runs`): set aside each changed folder's database and rename those Media Composer does not update for it (renamed.json flow). Undo: all media files back into the main folder (`plan` with per = MAX), emptied folders removed, old name back if free, main database set aside (+ rename for MC if needed); stops if a group folder is renamed for MC. Media Composer must be closed for rebalance, Start and undo. Tested end to end on a sparse disk image (200 files, limits 150 → 100 with rename).

## Crash safety of renames (journals)
renamed.json / rebalanced.json are saved before anything changes on disk (atomic tmp + rename). A folder is identified by MXF folder + current name + recorded MXF file names (Media Composer names are unique) – not by path alone: `find_moved` (lib.rs) finds the drive under another mount point (e.g. "/Volumes/Media 1" after a crash) and updates `mxf`. `rename::repair` (every start-page refresh, not during rename-back) also drops an entry whose renamed folder is gone while the original name holds all recorded files (app stopped between journal save and rename, or between rename-back and entry removal), and one whose renamed folder is gone while the drive's MXF folder is there (`Repair::Gone`: deleted or moved away by hand – otherwise it would wait for renaming back forever).

## Duplicates
`src/duplicates.rs` (user request 2026-11-09). "Find duplicates…" (Maintain › Duplicates, switched-on drives) → `find`: per MXF file the file mob ID from the header (`mxf::file_mob_id`), else the ID the folder's msmFMID.pmr lists for that name; files without any ID: name + size, then SHA-256 of the whole content (only those candidates). Same (dev, inode) counts once; Mountpoint workspaces (statfs f_mntfromname "mountpoint@"/"mirror@") are left out – they are the source drive's files. Copy that stays (`auto_keep`): known by its folder's database, then oldest, then path; click another copy to keep it. Groups with differing sizes are not ticked by themselves; groups with a copy in a folder renamed for Media Composer are blocked. The page shows at most 300 groups (`DUPS_SHOWN`), the report all. "Set aside" moves the other copies to "<drive>/MediaFiles Check Duplicates/<time>/<folder>/" (rename on the same drive), journal duplicates.json saved first (`Run`: moved (from, to, size), changed folders, db_done, `leftovers`). A folder left with only leftovers (see Rebalancing) goes into the same set-aside folder (`leftovers` journaled before it moves); undo recreates it with them first. Then page `dupsdone`: Start = `rewrite_folders` (database aside + rename for MC, same as rebalancing). History = page `runs` with `runs-kind` 1 (Rewrite databases, Undo: back only if the original place is free and the size matches, emptied set-aside folders removed, then the folders' databases are rewritten again). Tested on two sparse disk images (IDs, renamed copies, same-drive copies, no-ID files, differing sizes).
